🔄 异步回调生命周期管理模式

文档信息 | 难度: advanced | 预计用时: 35分钟 | 创建: 2026-08-12

📖 概述

在 C++ 异步编程中，回调函数在未来的某个时刻被调用，此时原始调用者可能已经析构。如果在回调中通过裸指针或引用访问已析构的对象，会导致 use-after-free——这是 C++ 异步编程中最危险的 bug 类型之一，通常表现为间歇性崩溃（SIGABRT/SIGSEGV），难以复现和调试。

本文档介绍一套完整的 异步回调生命周期管理模式：用 std::make_shared<Callback>(std::move(cb)) 将回调放入共享所有权包装器，在多层嵌套的异步回调链中按值捕获，确保回调对象和关联的服务对象在回调链的整个生命周期中存活。同时区分 Domain 服务层（shared_from_this() 穿透）和 Controller 层（[this] 安全）的捕获约定。

通过本文档，您将掌握：

2. 实现原理

2.1 shared_ptr 包装器

为什么用 shared_ptr<Callback> 而非 std::function 值传递：

方案 问题
std::function 值传递 move 后原始对象失效；多层嵌套需要反复 move，容易出错
std::function 引用捕获 &cb 悬挂风险——外层 lambda 析构后 cb 引用失效
shared_ptr<Callback> 共享所有权，多个 lambda 安全捕获；最后一个引用释放时自动析构

2.2 shared_from_this() 在 Domain 层的穿透

关键模式：

  1. 在方法入口处获取 auto self = shared_from_this()
  2. 每层 lambda 捕获 self（按值，shared_ptr 引用计数 +1）
  3. 嵌套 lambda 中通过 self-> 调用同一服务的方法
  4. self 在最后一个 lambda 析构时释放——此时整个回调链结束

2.3 Controller 层的 [this] 安全性

Controller 层 [this] 安全的条件：

条件 说明
HttpController<T, false> false = 非自动注册实例化，Drogon 用裸指针管理

不继承 enable_shared_from_this shared_from_this() 不可用
无析构风险 进程退出时 Controller 才析构，此时回调已完成

5. 常见问题

Q: shared_from_this() 什么时候会抛异常？

A: 当对象不是通过 shared_ptr 管理时（如栈对象或裸 new），shared_from_this() 会抛 std::bad_weak_ptr。因此 Domain 服务必须始终通过 std::make_shared<T>() 创建，不能栈分配或裸 new。

Q: 多层回调会不会导致 shared_ptr 引用计数爆炸？

A: 不会。每层 lambda 持有一个 shared_ptr，引用计数 +1。当某层 lambda 执行完毕后析构，引用计数 -1。最内层 lambda 析构时，如果计数归零，对象释放。这是一个栈式的引用计数增长/释放模式，最大引用计数 = 回调链深度。

Q: 回调被调用多次会怎样？

A: std::function 不限制调用次数。但在异步回调模式中，回调应该只被调用一次（成功或失败）。多次调用会导致上层逻辑混乱（如资源重复释放）。如果需要防重入，可以用 std::once_flag 或在 shared_ptr 包装器中加一个 bool called 标志。

📝 总结

关键要点:

  1. shared_ptr<Callback> 包装器：多层异步链中安全共享回调，避免 move 后失效
  2. shared_from_this() 穿透：Domain 层每层 lambda 捕获 self，确保服务对象存活
  3. **Controller 层 [this]**：进程级单例安全，不继承 enable_shared_from_this
  4. catch 必须回调：异常不能仅 LOG_ERROR 后 return，必须 (*sharedCb)(errorResult)
  5. 回调是最后一个参数：支持 && 移动语义，签名一致

💡 提示: use-after-free 是 C++ 异步编程中最阴险的 bug——它通常只在特定时序下崩溃，在测试中难以复现。shared_from_this() 穿透模式从设计层面消除了这类 bug 的可能性：只要每层回调都捕获 self，服务对象就一定存活到回调链结束。
