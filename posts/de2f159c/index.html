🧪 测试策略设计：分类、命名与分层契约测试

文档信息 | 难度: intermediate | 预计用时: 40分钟 | 创建: 2026-08-12

📖 概述

在 C++ 项目中，测试策略的设计直接影响 CI 效率和代码质量。没有分类体系的测试是一团乱麻——无法选择性运行、无法判断哪些测试是阻塞性的、无法在不同平台运行不同子集。

本文档介绍一套完整的测试策略设计：用 TestCategory 和 TestPriority 枚举定义测试分类体系，用 {Category}_{Priority}_{Module}_{Function}_{Scenario} 命名规范实现可过滤性，用分层契约测试确保多后端行为一致性，用无 DB 测试模式实现平台无关的快速反馈。还包括 Golden 快照测试和错误目录文档验证两种特殊测试模式。

🎯 学习目标

通过本文档，您将掌握：

  • TestCategory/TestPriority 分类体系的设计和 ctest 集成
  • 测试命名规范的 CI 强制验证
  • 分层契约测试针对多存储后端的运行策略
  • 无 DB 测试模式（-DOAUTH2_MEMORY_TESTS_ONLY=ON）的设计原理
  • Golden 快照测试和 API 文档验证测试

5. 常见问题

Q: 为什么用单个测试二进制而不是每个类别一个？

A: 单二进制让 ctest 基线直接可比——同一个二进制用 --gtest_filter 选择运行哪些测试。多二进制需要维护多个链接配置、多个 test_main、多个 CMake 条目。对于中等规模项目（几十到几百个测试），单二进制更简单。

Q: 契约测试的 GTEST_SKIP 会不会隐藏问题？

A: 不会。GTEST_SKIP 让测试在 ctest 中显示为 “SKIPPED” 而非 “PASSED”——你可以在 CI 日志中看到哪些测试被跳过及原因。如果 Memory 后端声称不支持事务但实际应该支持，事务测试被跳过意味着这个能力未被验证——这是一个可见的缺口，不是隐藏的问题。

Q: Golden 快照测试如何防止”快照腐化”？

A: 快照文件提交到 git 中。当响应格式变化时，测试失败，开发者必须更新快照文件并提交——git diff 会显示快照变化，PR 审查者可以看到格式变更。这确保格式变化是显式和可审查的。

📝 总结

关键要点:

  1. 分类体系：TestCategory × TestPriority 枚举 + ctest LABELS 实现选择性运行
  2. 命名规范：{Category}_{Priority}_{Module}_{Function}_{Scenario} 格式，CI 门禁验证
  3. 分层契约测试：同一套测试针对多后端运行，能力标志驱动 GTEST_SKIP
  4. 无 DB 模式：-DOAUTH2_MEMORY_TESTS_ONLY=ON 实现平台无关的快速反馈
  5. Golden 快照：自播种首次运行，git diff 审查格式变更
  6. API 文档验证：committed 文档与实现自动对比，防止文档漂移

💡 提示: 测试策略的核心价值不在于”写了很多测试”——而在于”能选择性运行正确的测试子集”。当 Windows CI 只需要 30 秒（Memory-only）而不是 5 分钟（全量 DB）时，开发者的反馈周期显著缩短，而这正是测试分类体系的回报。
