📦 Conan 2 + CMake Presets 集成模式

文档信息 | 难度: intermediate | 预计用时: 40分钟 | 创建: 2026-08-12

📖 概述

现代 C++ 项目面临三平台（Linux/Windows/macOS）、多编译器（GCC/MSVC/Clang）、多构建类型（Release/Debug/Sanitizer）的构建矩阵管理问题。手工指定 toolchain 文件、构建类型和编译器标志既容易出错又难以在 CI 中复现。

本文档介绍一种 Conan 2 + CMake Presets 集成模式：用 conanfile.py 作为三平台依赖的唯一描述符，用 CMakePresets.json 定义平台特定的构建预设，两者通过 Conan 生成的 conan_toolchain.cmake 桥接。CI 和本地开发者使用相同的 cmake --preset <name> 命令，确保构建路径一致。

🎯 学习目标

通过本文档，您将掌握：

  • conanfile.py 的选项管理和依赖锁定策略
  • CMakePresets.json 的继承体系设计和平台条件
  • Conan 到 CMake 的选项透传机制
  • 三平台构建矩阵的 preset 命名规范

4. 常见问题

Q: 为什么不用 conanfile.txt 而用 conanfile.py？

A: conanfile.txt 不支持 options（自定义选项）、generate() 方法（选项透传）和 build_requirements()（构建时依赖分离）。当项目需要条件编译或选项管理时，conanfile.py 是必需的。

Q: 为什么 MSVC preset 需要 CMAKE_POLICY_DEFAULT_CMP0091=NEW？

A: CMake 的 CMP0091 策略控制 MSVC 运行时库的选择方式。NEW 策略让 CMake 遵循 CMAKE_MSVC_RUNTIME_LIBRARY 变量而非硬编码 /MD，这对于让 Conan 管理运行时库（Debug 用 /MDd，Release 用 /MD）是必需的。

Q: Sanitizer preset 为什么用 Debug 构建类型？

A: Sanitizer 需要调试符号（-g）和禁用内联优化才能准确定位问题。Release 构建的内联会扭曲行号归属，优化可能消除触发 sanitizer 的代码路径。因此 linux-release-asan preset 实际上设置 CMAKE_BUILD_TYPE=Debug。

📝 总结

关键要点:

  1. conanfile.py 是三平台依赖的唯一描述符：选项管理、override 统一版本、test_requires 分离构建依赖
  2. CMakePresets.json 用继承体系管理平台预设：hidden base + 平台分支 + 构建类型/sanitizer 叶子
  3. tc.variables 桥接 Conan 与 CMake：Conan 选项透传为 CMake 缓存变量，实现条件编译
  4. preset description 嵌入 conan install 命令：开发者无需记忆命令参数

💡 提示: CMake Presets 的 condition 字段是实现平台自动选择的关键。CI 矩阵可以在每个平台 job 中运行 cmake --preset 而不用担心选错 preset——不匹配平台的 preset 会被自动隐藏。
