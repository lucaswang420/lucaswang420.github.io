🔄 跨平台管理脚本一致性模式

文档信息 | 难度: intermediate | 预计用时: 25分钟 | 创建: 2026-08-12

📖 概述

跨平台 C++ 项目通常需要 Bash（Linux/macOS）和 PowerShell（Windows）两套脚本。如果两套脚本各自独立维护，命令集合容易漂移——Bash 有某个命令但 PowerShell 没有，或同名命令的参数不同。开发者在平台间切换时遇到不一致的体验。

本文档介绍一种 跨平台管理脚本一致性模式：用 manage.sh 和 manage.ps1 封装项目的所有构建/测试/运行命令，两者从同一个 paths.env 加载路径，命令集合完全对等。CI 中用一个门禁脚本验证两种脚本的命令列表一致，确保任何命令变更都同步到两种平台。

3. 最佳实践

3.1 命令命名规范

  • build-backend、build-frontend：构建
  • test-backend、test-frontend：测试
  • run-backend：运行
  • dev-frontend：开发服务器
  • generate-models：ORM 生成
  • setup-db：数据库初始化
  • full-test：完整循环（构建+测试+API 测试）
  • docker-up、docker-down：Docker 编排
  • clean：清理

命名用小写+连字符，动词在前。两套脚本使用完全相同的命令名。

3.3 帮助信息对等

3.4 从 paths.env 加载

两种脚本都从 paths.env 加载路径变量（参见 [[paths-env-cross-platform-guide]]），确保路径定义只有一处。当目录迁移时，只改 paths.env，两套脚本无需修改。

4. 常见问题

Q: 为什么不用 Python 或 Node.js 写一个跨平台脚本，而是维护两套脚本？

A: 两种原因。第一，管理脚本需要在没有 Python/Node.js 环境的 CI runner 上运行（如最小化 Docker 镜像）。Bash 和 PowerShell 是各自平台的原生 shell，零依赖。第二，管理脚本经常需要调用 shell 特定功能（如管道、后台进程、信号处理），这些在 Python/Node.js 中实现不如直接用 shell 自然。一致性门禁脚本确保两套脚本不会漂移。

Q: 门禁脚本如何提取命令列表？

A: 用正则表达式从两种脚本的 case/switch 块中提取命令名。Bash 用 grep -oP 匹配 case 模式，PowerShell 匹配 switch 的字符串。提取后排序去重，用 comm 比较差异。这种方法是文本级的——不执行脚本，只静态分析。

Q: 如果某个命令只在特定平台有意义怎么办？

A: 将平台特定命令排除在一致性检查之外。例如 setup-db 如果只在 Linux 上运行（Windows 用 Docker），可以在门禁脚本的提取阶段排除。但更好的做法是让所有命令在所有平台上都有实现——即使某个平台是 no-op 或打印”此命令在当前平台不可用”。

📝 总结

关键要点:

  1. 两套脚本命令对等：manage.sh 和 manage.ps1 封装相同的命令集合，命名和参数一致
  2. 从 paths.env 加载路径：路径定义只有一处，两套脚本共享
  3. CI 一致性门禁：静态提取两种脚本的命令列表并 diff，不一致则阻断
  4. 命名规范：<verb>-<noun> 小写连字符，语义清晰

💡 提示: 一致性门禁的价值不在于”检测到了不一致”——而在于”让开发者知道新增命令时必须同步两套脚本”。这种门禁改变了开发者的行为模式，从源头上防止漂移。
