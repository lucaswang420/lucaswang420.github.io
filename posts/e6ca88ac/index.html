🔒 Value Object 不可变值对象模式 (C++)

文档信息 | 难度: intermediate | 预计用时: 25分钟 | 创建: 2026-08-12

📖 概述

在领域驱动设计（DDD）中，Value Object 是一种核心构件——它封装一个领域概念（如邮箱、货币金额、OAuth2 scope），在构造时验证自身不变量，构造后不可变。这种模式的核心优势是”消除无效状态”：如果一个 Value Object 成功构造了，它就一定是有效的，后续代码无需反复验证。

本文档介绍在 C++ 中实现 Value Object 模式的实践方法：构造函数抛 std::invalid_argument 拒绝无效输入、无 setter、提供 value() 访问和比较运算符。结合 Result<T,E> 模式，还可以在需要错误恢复（而非编程错误）的场景中使用静态工厂方法。

5. 常见问题

Q: 构造函数抛异常是不是不好？

A: 在 C++ 中，构造函数抛异常是惯用做法——它表示”对象无法成功构造”。标准库的 std::vector、std::string 都在构造时抛异常。Value Object 的不变量验证失败意味着对象不可能存在于有效状态——构造失败比允许无效对象存在更安全。

Q: 为什么不用 struct + 验证函数？

A: struct { std::string value; } + bool isValid(const std::string&) 的问题在于：你可以在不调用 isValid 的情况下设置 value。Value Object 模式利用构造函数将验证与构造绑定——不可能存在未验证的实例。

Q: Value Object 和 Entity 的区别？

A: Value Object 没有身份标识——两个 Scope("openid") 是完全等价的，可以互换。Entity 有身份标识——两个 User 即使名字相同也是不同的用户。Value Object 适合值类型（scope, URI, token），Entity 适合有生命周期的聚合根（client, user, session）。

📝 总结

关键要点:

  1. 构造即有效：构造函数验证不变量，构造成功意味着对象一定有效
  2. 不可变：无 setter，值语义复制，可安全共享
  3. explicit 构造：防止隐式转换绕过验证
  4. 独立类型：每个概念一个类型，编译器帮你检查类型混淆
  5. operator< 支持：可用于 std::set/std::map 键

💡 提示: Value Object 最大的价值不是”验证逻辑”，而是”消除无效状态的可能性”。一旦你习惯了”存在的对象一定有效”的编程模型，就很难回到反复验证 string 是否为空的世界了。
