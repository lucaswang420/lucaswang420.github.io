🔧 Git Hooks 代码质量自动化模式

文档信息 | 难度: intermediate | 预计用时: 30分钟 | 创建: 2026-08-12

📖 概述

在 AI 辅助开发的工作流中，代码质量保障不能仅靠人工审查和 CI。一种有效的补充策略是使用 工具级 Hooks（如 Claude Code 的 PreToolUse/PostToolUse hooks）在编码实时进行质量守护：自动格式化、提交前强制测试、保护生成代码不被手改、阻止凭证泄漏。

本文档梳理一套 Git Hooks 代码质量自动化模式，涵盖编辑后自动格式化、提交前测试门禁、文件保护（ORM 模型、生产配置）、凭证守卫（占位符检测），以及禁止危险操作（直接 push）。

🎯 学习目标

通过本文档，您将掌握：

  • PostToolUse hook 实现编辑后自动格式化
  • PreToolUse hook 实现提交前强制测试门禁
  • 文件保护策略：阻止对生成代码和敏感配置的修改
  • 凭证守卫：检测占位符凭证防止泄漏
  • 危险操作拦截：禁止 git push 直推

2. 实现原理

以下配置以 Claude Code 的 settings.json 为例（.claude/settings.json），但模式适用于任何支持 PreToolUse/PostToolUse hooks 的 AI 编码工具。

2.1 编辑后自动格式化（PostToolUse）

设计要点：

  • 匹配 Edit 工具调用（文件编辑后触发）
  • 只对 .cc、.h、.cpp、.hpp 文件运行 clang-format
  • 排除 models/ 目录（生成代码不应被格式化或修改）

2.2 提交前强制测试门禁（PreToolUse on git commit）

设计要点：

  • 拦截 git commit 命令（通过 Bash 工具的 input 检测）
  • 先检查 build/tests 目录是否存在（确保项目已构建）
  • 运行 ctest --output-on-failure，失败则阻断提交
  • 用 exit 1 阻断工具调用，错误信息反馈给 AI 工具

2.3 文件保护（PreToolUse on Edit/Write）

保护的文件类型：

文件 保护原因 替代方案
models/** ORM 生成代码，手改会被重新生成覆盖 改 schema 后重新生成
config.prod.json 生产配置含敏感信息 用环境变量覆盖
含 TODO.*REPLACE.*CREDENTIAL 的文件 占位符凭证未替换 先替换凭证再提交

2.5 危险操作拦截（Deny Rules）

设计要点：

  • git push 被完全禁止——强制通过 PR 流程进行人工审查
  • .env* 文件读取被拒绝——防止 AI 工具读取和泄漏环境变量中的密钥
  • Deny 规则比 hooks 更严格——直接拒绝工具调用，不执行

3. 最佳实践

3.1 Hook 的分层策略

层级 时机 能否阻断 用途
Deny 工具执行前 是（不执行） 危险操作完全禁止
PreToolUse 工具执行前 是（exit 1） 前置条件检查
PostToolUse 工具执行后 否（后处理） 自动格式化、修复

3.2 错误信息设计

Hook 阻断时的错误信息应该：

  • 说明原因：”ORM models are generated by drogon_ctl”
  • 提供替代方案：”Update the schema and re-run generate-models”
  • 不要过于技术化：AI 工具需要理解错误并采取替代行动

3.3 与 CI 的互补关系

保障层 时机 速度 覆盖范围
Hooks 编码实时 秒级 单文件操作
CI 提交后 分钟级 全项目构建+测试
人工审查 PR 审查 小时级 设计和逻辑

Hooks 不是 CI 的替代品，而是第一道防线——在错误传播到 CI 之前就拦截。

4. 常见问题

Q: Hook 检查失败后，AI 工具会怎么处理？

A: 当 PreToolUse hook 返回 exit 1 时，工具调用被阻断，错误信息被反馈给 AI 工具。AI 工具会读取错误信息并尝试替代方案——例如，当编辑 models/ 被阻断时，AI 工具会转而修改 schema 文件。

Q: 为什么不全部用 CI 而要加 hooks？

A: CI 的反馈周期是分钟级的——提交代码、等待 CI 运行、发现问题、修复、再次提交。Hooks 的反馈是秒级的——在编辑或提交的瞬间就拦截问题。这种即时反馈显著减少了修复成本。

Q: 如何避免 hook 误报？

A: Hook 的 matcher 应该精确匹配。例如 clang-format 只对 .cc/.h/.cpp/.hpp 文件触发，不对 .md 或 .json 触发。文件保护规则用路径正则而非简单字符串匹配，避免误伤同名但不同目录的文件。

📝 总结

关键要点:

  1. 三层质量保障：Deny（禁止）→ PreToolUse（阻断检查）→ PostToolUse（后处理修复）
  2. 编辑后自动格式化：消除格式争议，保持代码风格一致
  3. 提交前强制测试：确保未通过测试的代码无法提交
  4. 文件保护 + 凭证守卫：防止修改生成代码和泄漏凭证
  5. 与 CI 互补：Hooks 是秒级第一道防线，CI 是分钟级第二道防线

💡 提示: Hook 的错误信息质量直接影响 AI 工具的自我修复能力。好的错误信息不仅说明”不能做什么”，更要说明”应该做什么”——这样 AI 工具能在被阻断后自动转向正确的替代方案。
