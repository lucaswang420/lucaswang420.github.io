BFF (Backend For Frontend) Implementation Plan v3

Goal Description

Implement the BFF pattern to secure the OAuth2 flow for browser-based clients. The architecture uses unified API paths under /oauth2/ with separate controllers for clear separation of concerns.

Architecture Overview

API Design

Controller Method Path Auth Description
OAuth2Controller GET /oauth2/authorize - 授权端点
POST /oauth2/token client_secret 令牌端点 (Server-to-Server)
GET /oauth2/userinfo Bearer Token 用户信息
OAuth2SessionController POST /oauth2/session/login state BFF 登录 (换取 Session)
POST /oauth2/session/logout Session 清除 Session
GET /oauth2/session/userinfo Session 用户信息 (Session 模式)

Proposed Changes

Backend (OAuth2Backend)

[NEW] OAuth2SessionController.h

[NEW] OAuth2SessionController.cc

login 方法逻辑:

  1. 接收 code 和 state 参数
  2. 验证 state 与 Session 中存储的值一致 (CSRF 防护)
  3. 调用 OAuth2Plugin::exchangeCodeForToken
  4. 将 access_token, refresh_token 存入 Session
  5. 调用 req->session()->changeSessionId() 防止 Session 固定攻击
  6. 返回用户信息 JSON (不返回 Token)

logout 方法逻辑:

  1. 调用 req->session()->clear()
  2. 返回 204 No Content

userInfo 方法逻辑:

  1. 从 Session 获取 access_token
  2. 若过期，尝试用 refresh_token 刷新
  3. 返回用户信息

[KEEP] OAuth2Controller.cc

保持不变，继续服务 Server-to-Server 场景。

Verification Plan

Automated Tests

新增 test/OAuth2SessionControllerTest.cc:

  1. 模拟登录流程获取 Auth Code
  2. 调用 POST /oauth2/session/login
  3. 验证响应中 无 access_token
  4. 验证 Set-Cookie 包含 HttpOnly
  5. 使用 Cookie 调用 GET /oauth2/session/userinfo
  6. 验证返回用户信息

Manual Verification

  1. 启动前后端
  2. 浏览器 DevTools → Network
  3. 完成登录流程
  4. 确认:
    • /oauth2/session/login 响应 JSON 中无 Token
    • Cookie 带 HttpOnly; SameSite=Lax
  5. 刷新页面后仍保持登录状态
