🔒 Web API 安全实践集

文档信息 | 难度: advanced | 预计用时: 40分钟 | 创建: 2026-08-12

📖 概述

Web API 安全不是单一措施，而是纵深防御的多层实践集合。没有银弹——每层防御覆盖不同的攻击向量，缺一层就多一个攻击面。

本文档汇集一套经过验证的 Web API 安全实践集，涵盖认证层（PKCE 强制、渐进式锁定）、密码学层（恒定时间比较、敏感数据哈希存储）、传输层（TLS 统一）、配置层（生产配置保护、环境变量管理密钥）和供应链层（cosign 签名、SBOM 生成）。每条实践都是独立的，但组合使用形成纵深防御。

🎯 学习目标

通过本文档，您将掌握：

  • PKCE（RFC 7636）强制策略和实现
  • 渐进式账户锁定防止暴力破解
  • 恒定时间比较防止时序攻击
  • 敏感数据（密码、Token、Secret）的存储和日志安全
  • 供应链安全（镜像签名、SBOM）

2. 认证安全

2.1 PKCE 强制（RFC 7636）

PKCE（Proof Key for Code Exchange）防止授权码拦截攻击——公共客户端（SPA、移动应用）不使用 client_secret，攻击者可能截获授权码。PKCE 让客户端在授权请求时发送一个 code_challenge（验证挑战），在 token 交换时发送 code_verifier（验证器），服务端验证两者匹配。

2.2 渐进式账户锁定

渐进式策略的设计原理：

失败次数 锁定时长 目的
5 15s 阻止快速暴力破解
10 30s 增加攻击成本
15 60s 持续攻击者面临更长等待
20 永久 需要人工介入解锁

📝 总结

关键要点:

  1. PKCE 强制：公共客户端必须提供 code_verifier，防止授权码拦截
  2. 渐进式锁定：5/10/15/20 次失败递增锁定，增加暴力破解成本
  3. 恒定时间比较：防止时序攻击，Token/Secret 比较不可从响应时间推断
  4. 敏感数据哈希存储：密码、Token、Secret 都哈希存储，DB 泄露不可直接使用
  5. 密钥不入代码库：环境变量注入 + Hook 检测占位符凭证
  6. 供应链安全：cosign 镜像签名 + SBOM + SDK 校验和

💡 提示: 安全实践的核心不是”做了一件安全的事”——而是”每个攻击向量都有对应的防御”。纵深防御的价值在于：即使一层被突破，其他层仍然有效。单层安全（如只有 HTTPS）是必要的但不充分的。
